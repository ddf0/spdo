# Требования (выжимка из СПДО.001.ТЗ для разработки)

Первоисточник — `docs/reference/СПДО.001.ТЗ Техническое задание.docx`. При расхождении прав ТЗ.

## Роли

| Роль | Права |
|---|---|
| Пользователь | создаёт обращения, видит **только свои** обращения; чужие — только в рекомендациях (заголовок, статус, опубликованное решение) |
| Оператор | обрабатывает обращения, связи, решения, статусы, помечает конфиденциальность |
| Администратор | справочники, пользователи, параметры поиска, статистика |

Конфиденциальные обращения не попадают в рекомендации посторонним пользователям.
Права проверяются на сервере в каждой защищённой операции.

## Функции

Обязательные (Ф1–Ф15):

| ID | Функция |
|---|---|
| Ф1 | Регистрация: заголовок ≤ 200, описание ≤ 4000, категория, компонент; номер, дата, статус «Новое» |
| Ф2 | Черновик; текст не теряется при ошибке поиска |
| Ф3 | Поиск похожих при вводе; фиксация сеанса поиска (режим, версия модели, параметры) |
| Ф4 | Ранжированный список ≤ N (N ≤ 10): заголовок, статус, категория, S, вид связи |
| Ф5 | Карточка найденного обращения и его решения |
| Ф6 | «Помогло / не помогло» для решения; повторная оценка заменяет прежнюю |
| Ф7 | Пометка дубликатом; запрет связи с собой и прямых/косвенных циклов; статус «Закрыто как дубликат» |
| Ф8 | Связь «связанное» — статусы не меняет |
| Ф9 | Отклонение рекомендации с сохранением вердикта |
| Ф10 | Создание независимого обращения при наличии совпадений |
| Ф11 | Реестр: совместные фильтры (статус, категория, компонент), полнотекстовый поиск |
| Ф12 | Смена статуса по таблице переходов; публикация решения |
| Ф13 | История изменений: вид, было/стало, комментарий, автор, дата |
| Ф14 | Статистика: число сеансов, доля с подтверждённым дубликатом, доля отклонённых, дубликаты в top-3, recall@3 |
| Ф15 | Аутентификация, роли, признак конфиденциальности |

Желательные (Ф16–Ф22): настройка P1/P2/N/весов/модели; объяснение сходства;
уведомление авторов дубликатов в приложении; предложение категории;
обнаружение массового инцидента; группа дубликатов с основным обращением;
переиндексация при смене модели.

## Статусы

| Из | В | Условие |
|---|---|---|
| — | Новое | регистрация |
| Новое | В работе | оператор принял |
| Новое, В работе | Закрыто как дубликат | установлена связь «дубликат» |
| В работе | Решено | опубликовано решение |
| Новое, В работе | Закрыто | без решения, комментарий обязателен |
| Решено | Закрыто | подтверждение пользователем / по сроку |
| Решено, Закрыто | В работе | повторное открытие с комментарием |

Остальные переходы запрещены.

## Сущности

Обращение, Пользователь, Категория, Компонент, Связь, СеансПоиска, Рекомендация
(позиция, S и составляющие, вид, объяснение, вердикт), Решение, ОценкаРешения,
ИсторияИзменений, ПараметрыПоиска. Диаграмма: `docs/uml/06_class_domain.puml`.

## Алгоритм

```
S = w1·S_sem + w2·S_lex + w3·S_cat + w4·S_comp,   Σw = 1, w ≥ 0
S_sem  — косинус эмбеддингов «заголовок + описание» (pgvector)
S_lex  — TF-IDF/BM25, нормализованный в [0, 1]
S_cat, S_comp — 1 при совпадении поля, иначе 0
```

Начальные значения: w = 0,55 / 0,15 / 0,15 / 0,15; P1 = 0,80; P2 = 0,60; N = 10.

- S ≥ P1 → «возможный дубликат»; P2 ≤ S < P1 → «возможно связанное»; иначе не показывать.
- Два режима: базовый (только лексика, w1 = 0) и гибридный — сравнить в ПЗ.
- Все параметры — в конфигурации; для каждого сеанса сохранять режим, версию модели, параметры.
- Интерфейс явно пишет, что рекомендация автоматическая и может быть ошибочной.

## Нефункциональные

| Показатель | Норма |
|---|---|
| Подбор кандидатов, реестр ≤ 5 000, p95 | ≤ 2,0 с |
| Обычные операции интерфейса, p95 | ≤ 2,0 с |
| Одновременных пользователей | ≥ 10 |
| Объём реестра без деградации | ≥ 10 000 |
| RAM сервера с моделью | ≤ 4 ГБ |
| Диск с демо-набором | ≤ 10 ГБ |
| Восстановление после сбоя | ≤ 15 мин |
| recall@3 на проверочной выборке | ≥ 0,80 |
| Покрытие кода тестами | ≥ 70 % строк |
| Цикломатическая сложность функции | ≤ 15 |
| Индекс сопровождаемости модуля | ≥ 20 |

- Недоступность поиска не блокирует регистрацию: выводится предупреждение.
- Пароли — только хеши; пароли и токены не пишутся в логи; ввод проверяется на сервере.
- Основной сценарий создания обращения — на одной странице.

## Данные

- `data/synthetic/` — эталонный набор 100–150 обращений на русском:
  15–20 проблем × 4–6 формулировок, 20–30 тематически близких, ≥ 20 независимых.
- Набор делится на настроечную и **неизменяемую** проверочную часть (контрольная сумма).
- Внешние датасеты (AskUbuntu, CQADupStack, GitBugs) — только в `data/external/`, в git не попадают.

## Won't have

Мобильное приложение; таск-трекер (спринты, трудозатраты); обучение своей
модели; автозакрытие без человека; интеграции с почтой, мессенджерами,
внешними helpdesk; голосовые обращения; генерация ответов LLM;
микросервисы; дообучение на пользовательских данных.
