# Эталонный набор обращений

Файлы:

- `tickets.csv` — обращения: `id, title, description, category, component, status, split`;
- `groups.csv` — эталонная разметка: `ticket_id, group_id, kind` (`duplicate` | `related`);
- `checksum.txt` — SHA-256 проверочной части (`split = holdout`), фиксируется при заморозке.

Состав: 15–20 проблем × 4–6 формулировок, 20–30 тематически близких,
не менее 20 независимых. `split`: `tune` — настройка порогов и весов,
`holdout` — только измерение recall@3, не изменяется между релизами.

## Текущая версия

Набор вычитан исполнителями, проверочная часть зафиксирована:
SHA-256 `83029143c8a97653e2c47f0239905ffe3c95041a70f480f3a95906b0bc413f88` (`checksum.txt`).

129 обращений в службу технической поддержки вуза:

| Часть | Обращений | Разметка |
|---|---|---|
| 18 проблем по 4–6 формулировок | 82 | группы `P01`–`P18`, `duplicate` |
| Тематически близкие | 25 | группы `R01`–`R25`, `related`: обращение и первая формулировка близкой проблемы |
| Независимые | 22 | вне групп |

Формулировки одной проблемы различаются длиной, стилем (официальный,
разговорный, с опечатками), деталями и кодами ошибок; в 7 из 18 проблем
одна из формулировок отнесена пользователем к другой категории или
компоненту — так совпадение справочных полей не подсказывает ответ.
Тематически близкие обращения касаются той же системы, но другой
неисправности («VPN подключается, но внутренние сайты не открываются»
рядом с «VPN не подключается») и служат трудными примерами для порогов.

Проверочная часть — 7 проблем (32 формулировки — запросы для recall@3),
11 близких к ним обращений и 9 независимых; всего 52 обращения.

Справочники: 7 категорий («Сеть и подключение», «Учётные записи и доступ»,
«Электронная почта», «Оборудование и печать», «Учебные системы»,
«Корпоративные приложения», «Программное обеспечение») и 18 компонентов.

Порядок правки: изменить `tickets.csv` или `groups.csv`, затем

```bash
uv run spdo dataset freeze data/synthetic           # проверить формат и пересчитать сумму
uv run spdo dataset freeze data/synthetic --force   # если правка затронула проверочную часть
```

После официальной фиксации проверочная часть не меняется: правки — только
в настроечной части.

## Дополнительный набор SODD-ru

Для оценки качества на большой выборке используется дополнительный набор
SODD-ru — 1000 вопросов Stack Overflow (набор SODD) с машинным переводом на
русский язык и разметкой 500 пар: 250 дубликатов, 200 тематически близких
(`text_similar`, `tag_similar` → `related`), 50 независимых. Набор внешний и
в git не хранится (`data/external/`, лицензия CC BY-SA, атрибуция авторов —
в `ATTRIBUTION.md` рядом с набором).

Исходные файлы `pairs.csv`, `tickets_en.csv`, `tickets_ru.csv` положить в
`data/external/sodd-ru/raw/` и выполнить:

```bash
uv run spdo dataset convert-sodd data/external/sodd-ru/raw data/external/sodd-ru
uv run spdo dataset verify data/external/sodd-ru
uv run spdo dataset load data/external/sodd-ru --admin <администратор>
```

Преобразование формирует графы, которых нет в исходных данных:
`title` — первое предложение русского текста с кириллицей (до 200 символов),
`description` — русский текст (до 4000 символов), `component` и `category` —
по правилам распознавания технологии в английском тексте
(`spdo.analytics.sodd.RULES`); правила применяются к каждому обращению
отдельно, без учёта разметки пар. Дополнительные графы: `source_id` —
позиция в исходном наборе, `translation_review` — перевод отмечен для
проверки. Проверочная часть — 40 % пар каждого класса, выбранных
детерминированно по SHA-256 идентификатора пары.

Замечания к оценке на SODD-ru:

- признаки правил распознавания технологии подобраны по текстам всего
  корпуса, включая проверочную часть, но без обращения к разметке пар;
- дубликаты по построению чаще относятся к одной технологии, поэтому
  составляющие S_cat и S_comp коррелируют с разметкой; при сравнении режимов
  поиска recall@3 приводится и без них (w3 = w4 = 0);
- контрольная сумма защищает только обязательные графы проверочной части;
  `source_id` и `translation_review` в измерении не участвуют;
- повторное `convert-sodd` с изменёнными данными или правилами отклоняется,
  если меняет проверочную часть; осознанная замена — флагом `--force`;
- `load` перед загрузкой сверяет контрольную сумму; соответствие номеров
  сохраняется в `db_ids.csv`, повторная загрузка отклоняется.
